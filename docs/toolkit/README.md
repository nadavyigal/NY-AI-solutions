# AI Audit Toolkit

The delivery engine of the AI Value Sprint. Six steps, one template each.

| Step | Template | When | Client time |
|---|---|---|---|
| 1 | [01-intake.md](01-intake.md) | Before the fit call | 10 min, async |
| 2 | [02-pre-audit.md](02-pre-audit.md) | Before the discovery session | none |
| 3 | [03-discovery.md](03-discovery.md) | Sprint days 1-2 | 60-90 min per workflow |
| 4 | [04-audit-report.md](04-audit-report.md) | Sprint days 3-5 | none |
| 5 | [05-roadmap.md](05-roadmap.md) | Sprint days 5-6 | 45 min to walk through |
| 6 | [06-implementation.md](06-implementation.md) | Sprint days 6-10, then ongoing | varies |

Method and rules: [../service/delivery-workflow.md](../service/delivery-workflow.md).
First full run: [../clients/2026-08-30-michal-engagement-retro.md](../clients/2026-08-30-michal-engagement-retro.md).

**Three things every engagement must produce, or the sprint is not done:**
a measured baseline (step 3), a privacy path for every proposed workflow
(step 4), and a "leave this alone" finding (step 4).

Part of the practice: [../README.md](../README.md) is the operating index.
